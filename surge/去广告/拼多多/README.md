## 本阶段为什么暂停底栏改写

此前已处理样本的bottom_tabs和buffer_bottom_tabs均为三项，但用户界面仍可显示五项。这说明单凭改写后的导出内容不足以定位客户端实际采用的配置；缓存、皮肤、原生模型或其他配置尚无因果证明。继续对三项数组重复过滤没有新增证据。

本阶段不翻转未知实验开关、不删除皮肤、不封锁配置域名，也不用让视频页面打不开冒充隐藏按钮。

## 短时诊断流程

1. 从上述唯一地址更新，确认描述显示v0.2.1-test4及“临时诊断”。
2. 停用其他拼多多去广告/精简模块，只启用这一份；保持重写、MITM及自己的CA信任正常。高德等无关模块无需停用。
3. 开启捕获，在多任务界面彻底结束拼多多进程，再点图标启动，停留首页至底栏显示即可停止捕获。
4. 重点检查`api.pinduoduo.com/api/alexa/homepage/hub`，查看未过滤的result.bottom_tabs、result.buffer_bottom_tabs及相关字段。优先只保留相关配置请求，不必抓聊天、订单或浏览商品过程。
5. 若目标请求本次未发生，应记录未出现，不能拿旧包代替。不要公开分享查询参数、账号、Cookie、订单、精确位置或专属DNS。

取得原始配置后，再根据实际字段及客户端表现设计最小修复，仍发布到同一安装地址。

## 保留的开屏处理与限制

仅处理`api.pinduoduo.com/api/cappuccino/splash`：完整已见类型合同成立时清空splash_list，size及两个有效开屏标记置0，其他未知字段保留。0值空配置契约、缓存和客户端回退行为仍需真机验证；“没有看到开屏”不能在无接口命中记录时直接归因本规则。

没有远程脚本、Map Local、HTTPDNS/统计/长连接/CDN域名拦截，也不修改订单、个人页、首页商品或功能宫格。

## 兼容与回滚

建议Surge iOS6。原生jq最低需要iOS5.14+/Mac5.9+；CORE_VERSION>=20只是通用Body Rewrite门槛，不是jq完整最低版本证明。MITM只追加api.pinduoduo.com，不附带CA、不关闭服务器证书校验。

发布前保留test3及仓库固定提交备份；无须新增第二个订阅。异常时先停用本模块对照。没有进行新的Surge实机导入或底栏UI修复验证，本次仅诊断阶段切换。
