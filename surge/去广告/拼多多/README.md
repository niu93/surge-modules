## 底栏具体做法

只匹配`api.pinduoduo.com/api/alexa/homepage/hub`，同时处理两条数组：

```text
result.bottom_tabs
result.buffer_bottom_tabs
```

采用原插件的白名单，只保留完整link等于以下三个文件名的元素：

```text
index.html       首页
chat_list.html   聊天
personal.html    个人中心
```

这不是按“多多视频”或“双11”文案匹配；如果其他入口存在于上述数组、链接不在白名单内，会一并被过滤。未识别链接、缺少link的对象/null元素也可能按原作者语义被排除。与之前test3候选不同，本版不要求三类保留入口齐备，也不额外把完整URL/带查询参数的link归一化为文件名；完整link相等判断沿用原作者，不宣称它能覆盖未来所有路由。

加入根对象和数组类型检查；结构异常时透传，jq执行异常时返回该条规则的原始输入。保留剩余元素的id、group、图像及其他字段，不重新编号。原作者同一表达式中的all_top_opts图像/尺寸删除属于顶部分类精简，不在用户本次底栏目标范围内，因此没有加入。

## 开屏及其他范围

保留test4开屏规则逐字不变：处理`api.pinduoduo.com/api/cappuccino/splash`，已见完整类型合同成立时清空splash_list并把size/有效开屏标记置0。空配置契约与缓存/回退仍需真机验证；用户暂未看到开屏不单独证明每次规则命中。

模块只有2条原生jq；MITM只追加api.pinduoduo.com。不含远程JS、Map Local、统计/HTTPDNS/长连接/CDN域名阻断，不改顶部分类、首页商品、订单、聊天数据、个人中心、皮肤或实验开关，不修改CA或跳过上游证书校验。

## 已知限制与验收

原插件和此前版本都采用过双数组三链接过滤。已有HAR显示该类过滤后的数组是三项，但用户观察原生界面仍五项。**本次是按用户要求接回原作者处理逻辑，不是发现了新的必要字段或已经定位根因。** 不承诺本版必然隐藏当前App的两个入口，不把“页面打不开”当隐藏成功。

1. 从唯一地址更新，核对描述为v0.2.2-test5。
2. 停用其他拼多多模块，只启用这一份；高德等无关模块无需停用。
3. 开启重写、MITM，使用自己生成且已完全信任的CA。原生jq最低需要iOS5.14+/Mac5.9+；CORE_VERSION>=20仅是普通Body Rewrite门槛，建议当前Surge iOS6。
4. 完全结束拼多多后重开，观察开屏、底栏及首页/聊天/个人中心是否正常，不要求卸载、退出账号或清空数据。
5. 如仍五项，反馈同次模块版本、首页响应安全摘要和界面；不能将仅有匹配记录称作UI已修复。相同旧HAR不会增加原始底栏证据。
6. 若出现缺入口、空白、启动变慢等异常，先停用本模块对照；发布前已留固定提交备份，不需要第二个测试订阅链接。
