## 1. 启动开屏

精确端点：`api.pinduoduo.com/api/cappuccino/splash`。

在观察到的完整类型合同下：清空splash_list，同步将size、valid_splash_id及valid_splash_source_type置0，其他字段保留。两份有正文的Surge样本均可把列表1项变0项。

这是去除整个该接口开屏列表，不仅限第三方商业广告，也可能包含平台节庆开屏；与用户此前要求移除双11启动画面相符。有效标记0值的完整客户端行为仍待实机检验，不将其称作服务器保证的空配置协议。

## 2. 底栏候选

精确端点：`api.pinduoduo.com/api/alexa/homepage/hub`。

HAR原始响应明确出现五项；已观察的正常入口为index.html、chat_list.html、personal.html。对bottom_tabs和buffer_bottom_tabs分别处理：只有完整数组同时包含这三个正常入口时才按这三个完整link保留，缺字段、错误类型或不齐备时保留原数组；未知形状/null元素保留，保留对象的id/group/图像等原样。

这属于三入口白名单，其他带字符串link的导航（含buffer中的分类）也会排除，不是全局按视频/双11关键词搜索。没有删除皮肤、翻转实验开关或重新编号。

**重要：此前Surge已出现“响应数组三项、原生界面五项”，本版没有新的证据证明解决了这个问题。底栏规则只是对已观察数据合同的候选处理，不能承诺这次换独立实现就会成功。** 本地13份主页回放，其中3份原始五项变三项，其余原本已三项不变。

## 3. 首页商品流显式广告项（本次新增）

精确端点：`api.pinduoduo.com/api/alexa/cells/hub/v3`。

13份真实响应共130个商品，其中76个商品具有data.ad对象及非空字符串pkinfo、pubinfo。这些项同时出现竞价/投放追踪结构，而need_ad_logo可能为false，故不以显示广告角标作为判断标准。

仅在根/data/商品数组类型正确时，过滤满足上述明确结构的整个goods_list元素，而非只删除ad字段假装广告商品消失。未知结构、ad为null、缺少标记的项全部保留。

本地回放76项被筛除，54项其余商品保留；data.ext、has_more、org、预加载和刷新策略等全部原样。不屏蔽商品图片，不清空整个商品接口，不伪造无下一页。

**风险/限制：这是结构性广告候选识别，不是逐件商品商业合同的人工审计。** 不同客户端版本可能改变schema；分页少于原批次可能导致空位、额外加载或列表补充请求。尚未验证App布局、刷新和滚动行为。没有承诺去除所有商品推荐，更不会把普通推荐都当广告。

## 4. 明确不处理的范围

- 个人中心9块9横幅及其下方所有商品推荐。
- 聊天页顶部秒杀横幅、会话下方全部商品推荐。
- 扫码取件页、订单、钱包、优惠券、客服、物流或普通会话。

原因：Surge样本里若干候选接口虽然出现，但对应正文已经被旧模块改成`{}`；个人页综合响应也已有改写日志。空对象和已删字段不能用来反推原始布局或广告边界。已见个人页show_recommend_feed_banner为false，仍不足以定位圈选内容。不加入三个盲目空响应映射或阻断长连接来强制回退。

底栏在响应层三项，亦不证明原生UI已采用；消息或推荐接口未出现在短抓包中，不等于证明完全没有HTTP回退。此前对此的过强推断不作为本模块依据。

## 安装与回滚

1. 在Surge中更新原模块，确认描述为v0.3.0-test13。名称将显示“拼多多·HAR独立去广告测试”。**停用其他拼多多模块，只启用这一份**，不要保留另一份test12同时启用。停用旧模块并不会删除已存客户端状态。
2. 开启重写、MITM，使用自己生成且已信任的CA。MITM按主机生效，不仅是这3条路径；模块不附带CA，不关闭上游证书校验。
3. 原生jq最低Surge iOS5.14+/Mac5.9+；CORE_VERSION>=20只是通用Body Rewrite门槛，建议当前iOS6。超过宿主正文限制可能放弃修改；本模块没有提高全局缓冲上限。
4. 分别核对开屏、底栏、首页商品流及正常翻页。若空位、无法刷新或功能异常，停用本候选，保留原模块供对照；不要求卸载、清数据、退出账号。

本版已替换线上test12，但没有主动修改设备运行配置；需用户从同一地址更新。尚未完成Surge实机导入、实际匹配和UI/业务验证。异常时先停用，本次备份可通过同一测试地址回退。
